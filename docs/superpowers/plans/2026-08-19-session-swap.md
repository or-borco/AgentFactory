# Post-Session Reassignment & Codebase Swap Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let a task's Assignee and Codebase be changed even after a session exists (when idle, not mid-run) by detaching the task from its old session — reusing the existing teardown job and "start a session" flow rather than building new sandbox-provisioning code — and keep the old session's transcript browsable afterward.

**Architecture:** "Swap" = detach. `PATCH /api/tasks/[taskId]` gains a teardown trigger for the case where a client explicitly nulls `sessionId`. Two dropdowns (Assignee, widened; a new Codebase) share one confirm-then-detach client action. `sessions` gains a `task_id` back-reference so past sessions for a task can be listed and viewed read-only.

**Deviation from the spec, discovered during planning:** the spec called for a new `GET /api/tasks/[taskId]/sessions` route and a `listSessionsForTask` repository function. Neither is needed: `apps/web/src/lib/mock/context.tsx` already fetches every session for the org on mount (`GET /api/sessions` with no query param returns all of them, per `listSessions(orgId, undefined)`), so `state.sessions` client-side already has everything a "previous sessions" list needs — the same way `sessionsForAgent` already works today by filtering that same already-loaded array. Task 5 adds a `sessionsForTask` selector following that exact precedent instead of a new endpoint. This still fully satisfies the spec's goal (a browsable session history); it's a smaller implementation of the same requirement, not a scope cut.

**Tech Stack:** Next.js 16 App Router, React, TypeScript, Drizzle ORM + drizzle-kit (Postgres), BullMQ (`@agentfactory/queue`), Vitest + Testing Library.

## Global Constraints

- All user-facing strings go through `useTranslation()` / `t()`, sourced from `apps/web/src/lib/i18n/dictionaries/en.ts` — never hardcode UI text.
- Client components never import from `mock-store.ts` directly — use `useMockBackend()`.
- `apps/web/src/app/(app)/tasks/[taskId]/page.tsx` uses plain inline `style={{}}` objects throughout, not Tailwind — match that convention for anything added to it. `packages/shared` components (used only on `tasks/new` and `tasks/[taskId]/edit`) are Tailwind-based — match that convention there instead.
- No test infrastructure exists for `tasks/[taskId]/page.tsx`, `tasks/[taskId]/edit/page.tsx`, or any `app/api/**/route.ts` in this repo — don't add new test files for page- or route-level wiring. Repository-level code (`packages/db/src/repositories/*.ts`) does have test coverage — extend it for anything touched there.
- Swap is only reachable when `!task.sessionId || !isRunning` — never mid-run. There is no run-cancellation mechanism anywhere in this codebase; building one is out of scope.
- A swap clears `task.prNumber`/`task.prUrl` (the old PR is unlinked, not touched on GitHub) and reverts `task.status` to `assigned` (if an assignee is set) or `open` (if not) — the exact rule `handleAssigneeChange` already applies today, reused rather than reinvented.

export async function listSessions(orgId: number, agentId?: number): Promise<Session[]> {
  const rows = await db
    .select()
    .from(sessions)
    .where(agentId !== undefined ? and(eq(sessions.orgId, orgId), eq(sessions.agentId, agentId)) : eq(sessions.orgId, orgId));

export async function getSession(id: number): Promise<Session | undefined> {

      taskId,

```ts
export async function PATCH(req: Request, { params }: { params: Promise<{ taskId: string }> }) {
  const ctx = await requireAuthContext();
  if (!ctx) return NextResponse.json({ error: "Unauthorized" }, { status: 401 });
  const { taskId } = await params;
  const body = await req.json();
  const before = await getTask(Number(taskId));
  const task = await updateTask(Number(taskId), body);

  // A task that's reached a terminal status no longer needs its warm sandbox — tear it down.
  // The worker owns the docker socket, so this only enqueues the job (see the DELETE handler below).
  if (body.status && TERMINAL_TASK_STATUSES.has(task.status) && task.sessionId) {
    await enqueueSandboxTeardownJob(task.sessionId);
  }

  // A swap (reassign/re-codebase after a session already exists) explicitly detaches the task
  // from its session by setting sessionId to null — tear down that old session's sandbox too.
  // Read the pre-update value: by the time updateTask returns, task.sessionId is already null.
  if (body.sessionId === null && before?.sessionId) {
    await enqueueSandboxTeardownJob(before.sessionId);
  }

  return NextResponse.json(task);
}
```
